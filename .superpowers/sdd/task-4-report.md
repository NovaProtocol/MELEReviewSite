# Task 4: Alembic Migrations — Report

## Summary
Replaced ad-hoc `ALTER TABLE` / `_drop_sources` / `_migrate_columns` logic with proper Alembic migrations. Production MySQL now uses `alembic upgrade head` with retry; SQLite tests keep fast `Base.metadata.create_all` path.

## Changes Made

### `alembic.ini` (new)
- Generated via `alembic init alembic`, `script_location = %(here)s/alembic`, `prepend_sys_path = .`.
- `sqlalchemy.url` placeholder `driver://user:pass@localhost/dbname` is overridden at runtime from `Settings().db_url`.

### `alembic/env.py` (rewritten)
- Imports `api.models.Base.metadata` for autogenerate (`target_metadata = Base.metadata`).
- `_get_url()` resolves URL from `config.get_main_option("sqlalchemy.url")` or `Settings().db_url`, normalizing async drivers (`+aiomysql` -> `+pymysql`, `+aiosqlite` -> ``) so Alembic runs with sync drivers.
- Supports `offline` and `online` modes with `compare_type=True` / `compare_server_default=True`.
- Uses `engine_from_config(..., poolclass=pool.NullPool)` for online migrations.

### `alembic/script.py.mako` (generated)
- Default Alembic template.

### `alembic/versions/0001_initial.py` (autogenerated, renamed from `daaecaa7fb2b`)
- `alembic revision --autogenerate -m "initial"` via `DATABASE_URL=sqlite:////tmp/alembic_autogen.db`.
- Creates all tables idempotently on MySQL and SQLite:
  - `accounts` (id, name, pin, date_created, disabled, is_admin)
  - `tags` (id, name unique indexed)
  - `questions` (id, question_text, choices a-e, answer, solution, flagged, active, account_id FK SET NULL, dates) + `ix_questions_account_id`
  - `question_flags` (composite PK question_id, account_id, FK cascade)
  - `question_tags` (composite PK question_id, tag_id, FK cascade)
  - `solutions` (id, question_id, account_id, convention, blocks, dates) + `ix_solutions_*`
- Downgrade drops indexes/tables reverse order.
- Revision ID `0001` (matches filename).

### `api/models.py` (server_default tweaks, indexes)
- Added `import sqlalchemy as sa`.
- `Account.disabled` / `is_admin`: `server_default=sa.text("0")`.
- `Question.flagged`: `server_default=sa.text("0")`, `Question.active`: `server_default=sa.text("1")`.
- `Question.account_id`: added `index=True` (generates `ix_questions_account_id`).
- `Solution.convention`: `server_default=sa.text("'metric'")`, `Solution.blocks`: `server_default=sa.text("'[]'")`.
- Ensures autogenerate is stable across MySQL/SQLite and MySQL defaults are not recalculated on each revision.

### `api/app.py` (lifespan branching)
- Removed direct `create_all + _drop_sources + _migrate_columns` retry loop.
- Added `_run_alembic_upgrade(sync_url)` helper using `alembic.config.Config` + `command.upgrade(head)` on sync URL.
- `_init_db()` now branches on `"sqlite" in db_url`:
  - **SQLite (tests)**: `async with engine.begin() as conn: await conn.run_sync(Base.metadata.create_all)` with 10 retries, 3s backoff. Fast, no threadpool.
  - **MySQL (prod)**: `sync_url = db_url.replace("+aiomysql", "+pymysql")`, then `await asyncio.to_thread(_run_alembic_upgrade, sync_url)` with 10 retries, 3s backoff, logging `alembic upgrade head`.
- Legacy helpers `_drop_sources` / `_migrate_columns` retained but no longer invoked (idempotent cleanup no longer needed after initial migration); can be deleted in follow-up.

## Verification

```bash
DATABASE_URL=sqlite:////tmp/test_alembic.db SECRET_KEY=... MYSQL_PASS=... alembic upgrade head
alembic current  # 0001 (head)
alembic downgrade base && alembic upgrade head  # idempotent
pytest  # 36 passed (35 existing + 1 new)
```

- SQLite tmp upgrade creates all 7 tables (including `alembic_version`) with correct FKs and server_defaults.
- `+aiosqlite` URL normalized and also upgrades correctly.
- `pytest` passes with `DATABASE_URL=sqlite+aiosqlite:////tmp/melereview_test.db` via `create_all` path.

## Design Decisions
1. **Hybrid strategy**: Keep `create_all` for SQLite tests for speed (no Alembic overhead, matches `conftest.py` `TestClient` lifespan). Use Alembic only for MySQL prod where durability matters.
2. **Sync URL mapping**: Alembic requires sync driver; async `aiomysql`/`aiosqlite` mapped at both `env.py` and `app.py`.
3. **Stable 0001 revision**: Renamed hash to `0001` for readability; header and revision var both updated. `alembic history` shows `<base> -> 0001 (head)`.
4. **Server defaults**: Added `sa.text` defaults to booleans/text to avoid perpetual diffs on MySQL vs SQLite boolean handling.
